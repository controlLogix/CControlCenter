## How to run the phase gate

1. Freeze the candidate commit, contract/dependency/config versions and fixture set.
2. Run the phase criteria and affected earlier regression tests. Use real broker, actual clients and hardware where the claim requires them.
3. Inject the listed failures and inspect authoritative state plus correlated evidence. Screenshots alone cannot prove ownership or delivery.
4. Rehearse the documented recovery and rollback boundary. Record incomplete environments separately from failures and passes.
5. Obtain independent review and the authorized phase-advancement decision. Material changes invalidate affected evidence.
6. Keep the branch unmerged until Ryan has reviewed it with Nick and explicitly authorizes merging.

## Quality evidence

Schema tests establish format and compatibility. Deterministic state-machine tests establish defined transitions. Real broker tests establish delivery/reconnect behavior in a pinned topology. Actual-host tests establish integration capabilities. Live labeled inference establishes measured decision quality. Hardware tests establish the explicitly exercised tool/device compatibility. None of these substitutes for another.

Adversarial task execution qualifies the launch worker boundary in P04. Hostile third-party plugin confinement is a separate P14 promise. Both must state their tested threat model.

For Jev and skills, use the nine evaluation gates and per-record criteria in [jev-coverage.json](jev-coverage.json). Preserve tuning/validation/holdout separation and complete outcome costs.
