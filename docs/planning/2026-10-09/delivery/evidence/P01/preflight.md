## Candidate verification, gaps and rollback

P01 adds two-language schema and real-broker storage/leaf fixtures. Candidate evidence must record versions, commands, exit status, captured output, source/configuration hashes, separate broker accounts and actual cleanup. Include malformed/version/scope rejection, duplicate/reordered/replayed messages, deadlines/cancellation, lost acceptance acknowledgment, competing conditional writes, batch interruption, restart/replay and authoritative reconciliation. Unsupported cross-stream transactions and external side effects must be rejected or assigned explicit recovery behavior; a transport acknowledgment is never transaction proof.

This preflight has not executed native macOS, CI OS jobs, actual terminal providers, CPython 3.12 bytecode comparison, full dashboard/tmux isolation, historical communication fixtures or the new two-language broker spikes. Existing WSL reports and P00 contract checks do not close these gaps. Verify current availability when running them; do not infer Docker, hardware, paid provider credentials or native-host access from earlier planning. Missing required environments stay visible and prevent the corresponding qualification claim.

No runtime data migration is applicable to these isolated P01 additions: no existing writer, stream, database, credential store or pending reservation is cut over. Later phases still own production migration/replay and legacy-adapter comparisons. Rollback removes or disables only the new isolated path while preserving old tests, source, history and evidence. Any reverted baseline repair reopens its finding and invalidates affected acceptance. These decisions preserve all capabilities; there is no reduction requiring a scope exception.
