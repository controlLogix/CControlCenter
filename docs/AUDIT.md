# Voice CLI audit — 1.0.0 (2026-09-22)

Scope: every module in `src/voicecli` at 0.1.0 (commit `7c85584`), how it was launched
(`install-shortcuts.ps1` → `pythonw -m voicecli`), its data on disk, and its dependencies.
The goal for 1.0.0: a standalone Windows app that starts at sign-in, stays pinned to the taskbar,
and is safe to leave running all day.

Severity: **High** = a security hole or data loss, or the app fails in normal use. **Medium** = a
realistic failure or exposure. **Low** = hygiene.

## Security and privacy

| # | Sev | Finding (0.1.0) | Resolution (1.0.0) |
|---|---|---|---|
| S1 | High | The HTTP API on `127.0.0.1:47821` had no authentication (`server.py:74-108`). Any local process could lock typing onto another window (`POST /target`), switch mics or quit the app. Any **web page** could do the same with a simple cross-site POST, because the body was parsed whatever its Content-Type (`server.py:70-72`). A DNS-rebinding page could stream live transcripts from `GET /events`, because Host was never checked. | Every endpoint except a bare liveness `/health` needs `Authorization: Bearer <token>` (32-byte random token in `%APPDATA%\voicecli\api-token`, compared in constant time). Host must be `127.0.0.1:<port>` or `localhost:<port>`. Any request with an `Origin` header is refused. POSTs must be `application/json`. `tests/test_server.py` covers each rule. |
| S2 | Medium | On Windows the listening socket used `SO_REUSEADDR` (the `http.server` default), which lets another process bind the same port and receive requests meant for voicecli. | `SO_EXCLUSIVEADDRUSE`, with `allow_reuse_address` off (`server.py`, `_Server`). |
| S3 | Medium | The request body was read to whatever `Content-Length` said (`server.py:71`): a memory exhaustion vector. | 64 KiB cap (413); negative or invalid lengths get 400; the body must be a JSON object; a 10 s read timeout drops stalled clients. |
| S3b | Low | Early rejections (401/415/413) closed the socket with the request body unread, and Windows then resets the connection, so clients saw a connection error instead of the status. | Error replies first read and discard up to 1 MiB of pending body. Found by the new tests. |
| S4 | Medium | Each `/events` subscriber had an unbounded queue, and there was no limit on subscribers (`server.py:38-40, 111-113`). A client that stops reading grows memory forever. | At most 8 subscribers (503 after that); each queue holds 500 events and drops the oldest. |
| S5 | Medium | Everything said was written in plain text to `%APPDATA%\voicecli\voicecli.log`, a file that never rotated (`cli.py:68-71`, `app.py:45-51`). The log on this machine held every dictated phrase. | Logging moved to `%LOCALAPPDATA%\voicecli\logs\voicecli.log`: machine-local, not synced by roaming profiles, rotating at 1 MB × 5. Spoken text and window titles (which name documents, videos and chats) are replaced by their length unless `log_transcripts` is true in `config.json`. The process name is kept. Partials, mic levels and faster-whisper's per-call chatter are not logged. The old `%APPDATA%\voicecli\voicecli.log` is no longer written; delete it to remove old transcripts. |
| S6 | Medium | Models were fetched from Hugging Face on first run at whatever revision `main` pointed to, with no integrity check (`engine.py:63-66`). This was a supply-chain risk, and the app could not work offline or behind a proxy. | The two default models ship inside the install, pinned to Hugging Face commits and checked against SHA-256 values at build time (`packaging/fetch_models.py`). At runtime, bundled models are used first, and downloads are **off** (`HF_HUB_OFFLINE=1`, `local_files_only`) unless `allow_download` is set. Hugging Face telemetry is disabled. |
| S7 | Low | In follow-focus mode, text goes to whatever window has focus, which might be a chat or a password prompt. | Accepted: this is the feature. It is mitigated by the focus guard (desktop, taskbar and the overlay are never typed into), by the window lock (Ctrl+Alt+L or the API), and by "not typed" feedback. Use the lock when talking to one CLI. |
| S8 | Low | The exe and installer are unsigned, so SmartScreen warns on first run and enterprise allow-listing by publisher is not possible. | `packaging/build.ps1` signs and timestamps the exe, the installer and the uninstaller when `VOICECLI_SIGN_THUMBPRINT` names a code-signing certificate. **Open:** needs a certificate. |
| S9 | Low | Any process in the same Windows session can signal the `Local\VoiceCLI.Show` / `Local\VoiceCLI.Quit` events. | Accepted: same-session processes can already send the window `WM_CLOSE`. The events carry no data. |
| S10 | Info | Windows (UIPI) blocks `SendInput` into elevated windows. | Accepted and documented: voicecli reports "typing failed". Run it elevated only if the target CLI is elevated. |

## Reliability

| # | Sev | Finding (0.1.0) | Resolution (1.0.0) |
|---|---|---|---|
| R1 | High | If the saved mic was missing at start, the app **exited** (`app.py:184-187`). With start-at-sign-in and a wireless headset that is off at boot, Voice CLI would silently never run. With no input devices at all, `resolve_device(None)` raised `IndexError` (`audio.py:60`). | Startup falls back to the Windows default mic, or runs with no mic, and says so in the overlay and a tray notification. It never exits. |
| R2 | High | There was no recovery when the mic disappeared mid-session (headset off, USB unplugged). The stream stalled and push-to-talk silently did nothing until a restart. | A watchdog (`App._watch_mic`) spots a stream with no audio for 3 s. It re-scans devices (PortAudio only lists devices at startup) and reopens the chosen mic, or the default meanwhile. Once Windows lists the chosen mic again (checked through the live MME device list, which does not disturb the open stream), it switches back. Each change shows as a tray notification. |
| R3 | Medium | The single-instance check was an HTTP probe of port 47821 (`cli.py:13-26`). Any other program answering on that port made voicecli exit, thinking it was already running. Two quick launches could both pass the probe. | A named mutex (`Local\VoiceCLI.Instance`). A second launch signals `Local\VoiceCLI.Show` and exits within milliseconds, before loading numpy or Whisper. The installer runs `--quit`, which signals the `Quit` event and returns only once the old process has fully exited (the mutex is released by Windows at process exit, not earlier), so no file is still locked when it is replaced. |
| R4 | Medium | Config saves were not atomic and were called from several threads (overlay drag, API, menu) (`config.py:54-57`): a crash or race could leave truncated JSON. Loading discarded the **whole** file on any parse error, and an ill-typed value (for example `"opacity": "high"`) crashed later. | Saves write a temp file then `os.replace`, under a lock. Loading validates every field against its type and range, keeps the valid ones, and logs and defaults the rest. Command-line flags go through the same checks. |
| R5 | Medium | The final transcription (about 1 s) ran on the capture thread (`engine.py:202`). Audio backed up while it ran, and push-to-talk state was read when the backlog was processed, not when it was recorded. A quick second press could clip the start of a phrase or pull in old audio. | Finals run on their own worker (a bounded queue of 3; overflow is reported as `discard: busy`). Capture never waits. `test_slow_final_does_not_stall_capture` pins this. |
| R6 | Medium | In windowed mode an uncaught exception in any thread vanished, and startup failures went to a log nobody reads. | `sys.excepthook` and `threading.excepthook` log with the traceback. A fatal main-thread error shows a dialog pointing at the log. A failed partial or final transcription is logged and reported, and no longer kills its thread. |
| R7 | Low | `set_mic` failing, and then failing again to reopen the previous mic, raised from inside the error handler, which left no mic and a misleading error. | Both failures are handled. The watchdog keeps looking. |
| R8 | Low | Hotkey conflicts (another app owns Ctrl+Alt+L) show only briefly in the overlay. | Accepted. They are also logged, and the keys can be changed in `config.json`. |

## Operations and packaging

| # | Sev | Finding (0.1.0) | Resolution (1.0.0) |
|---|---|---|---|
| O1 | High | The app ran from a source checkout through `pythonw -m voicecli` (`install-shortcuts.ps1`). That needed uv and Python on the machine and broke if the venv moved or was re-synced. | `VoiceCLI.exe`: a windowed PyInstaller one-folder build with version info and the app icon, carrying its own Python runtime and models. `install-shortcuts.ps1` is removed. |
| O2 | High | Nothing started it at sign-in. | Per-user Run entry `VoiceCLI` → `"…\VoiceCLI.exe" --startup`, written by the installer (on by default) and toggled from the tray or overlay menu. It respects and clears Task Manager's "disabled" flag. |
| O3 | Medium | There was no installer, uninstaller, silent deployment path or upgrade story. | `VoiceCLI-Setup-<ver>.exe` (Inno Setup) installs per user with no admin rights to `%LOCALAPPDATA%\Programs\VoiceCLI`. It adds Start menu and desktop shortcuts with an AppUserModelID, an Apps & Features entry, `/VERYSILENT` deployment and a clean upgrade (the running app is asked to quit, and stale runtime files are removed). Uninstall removes the files, shortcuts and startup entry and keeps settings. |
| O4 | Medium | There was no visible presence when the overlay was hidden, and no way to quit except a hotkey or the API. | A notification-area icon: click to show the overlay; its menu has Show/Hide, Start with Windows, Open log folder, the version and Quit. It survives Explorer restarts. |
| O5 | Medium | There were no automated tests. `tests/` held three manual scripts. | A pytest suite of 36 tests: config validation, API security, single instance, autostart, log redaction and rotation, device matching, mic recovery (stall, headset off and on, no mic), and engine phrase logic with synthetic audio. The manual scripts moved to `tests/manual/`. `build.ps1` runs the tests and then `VoiceCLI.exe --self-test`, which loads the bundled models offline and transcribes. |
| O6 | Low | Not pinned to the taskbar. | Windows 11 has no supported way for a program to pin itself (the `taskbarpin` verb is gone, and the policy XML route needs Pro or Enterprise plus admin). The user pins once: Start → right-click **Voice CLI** → **Pin to taskbar**. The pinned icon starts the app, or brings the running one forward. |

## Not changed, by design

- Typing uses `SendInput` with Unicode, and switches focus to a locked window and back. Writing into a background console without taking focus (`WriteConsoleInput` via `AttachConsole`) would avoid the brief focus flip. It needs mapping each Windows Terminal tab to its console process, so it is a candidate for the ByteDesk plugin work.
- The engine uses CPU int8 inference: no GPU dependency, predictable on any machine.
