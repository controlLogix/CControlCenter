# Pure transition fixture models

`state-machines.json` promotes the five P00 state tables and all 68 edges without changing their transitions. Its promotion history records the source hash and added cancellation invariant. These models describe plugin, task, delegation, attempt and effect behavior.

The independent Python and TypeScript evaluators accept `evaluateTransition` with a `request` object containing `schemaVersion: "1.0.0"`, `machine`, `ownerSnapshot`, `intent`, `authority` and `guards`. All objects have closed field sets. The owner snapshot carries entity, hub and scope IDs, current state/revision and a cancellation flag. The intent carries entity ID, expected revision, event, operation ID and payload digest. Authority carries matching entity/hub/scope, an exact actor role and a nonempty list of evidence references. Each required guard needs an opaque, nonblank evidence reference; booleans and unknown guard names are rejected.

Exact nested fields are `ownerSnapshot: {entityId, ownerHubId, scopeId, state, revision, cancellationPending}`, `intent: {entityId, expectedRevision, event, operationId, payloadDigest}` and `authority: {entityId, ownerHubId, scopeId, actorRole, evidenceRefs}`. `guards` maps exactly the selected edge's required guard names to evidence references. Authority references are unique, with 1–64 entries; each reference has 1–512 characters and must contain non-whitespace text. Identifier and digest syntax follows the version 1 wire contracts.

Success returns `{machine, entityId, ownerHubId, scopeId, fromState, state, previousRevision, revision, cancellationPending, operationId, payloadDigest, event, evidenceRefs, guardEvidence}`. The CLI wraps this result using the existing `{ok, result}` response. Every successful edge increments the revision, including an observation self-loop. Revisions remain safe integers. An accepted pure transition does not prove persistence or justify automatic operation replay.

The caller supplies a trusted fixture snapshot and already resolved evidence. The evaluator does not authenticate references, grant authority, fetch evidence, persist records or reconcile retries. A role string or a plausible reference from an untrusted caller is not authorization. The returned next state/revision is only a candidate transition. A production owner must authenticate and revalidate before a conditional durable commit.

Cancellation remains recorded through uncertain outcomes. An attempt with cancellation recorded cannot use `reconcile_running` or `reconcile_terminal`, even if a fixture supplies a contradictory `no_pending_cancellation` reference. Keep the uncertain owner state and record any receipt separately, then use the existing cancellation reconciliation edges. Moving directly to `completion_reported` would otherwise strand cancellation because that state has no cancellation-reconciliation edge in the accepted table. No table edge is silently rewritten.

`cancellationPending` clears only on a guarded transition to `cancelled`; the transition history still records the cancellation. A false flag means cancellation is not recorded in this snapshot. Reconciliation may discover a newer cancellation through trusted `cancellation_still_pending` evidence and enter `cancel_requested`. That evidence must be resolved by the owner; the oracle cannot verify a caller's assertion.

Revision values follow JSON integer semantics: `3` and `3.0` are equivalent, while booleans, fractional values and unsafe integers are rejected. Evidence references contain 1–512 Unicode code points and at least one character outside this explicit blank set: U+0009–000D, U+001C–0020, U+0085, U+00A0, U+1680, U+2000–200A, U+2028, U+2029, U+202F, U+205F, U+3000 and U+FEFF. Both SDKs use these exact bounds rather than their languages' different string-length or whitespace defaults.

`cancellationPending` is true in `cancel_requested` and stays true through `effect_uncertain`. It clears only when entering `cancelled` after that edge's confirmation guards pass. The cancellation request remains in the returned transition evidence and surrounding history; clearing the pending flag does not erase it. Snapshots claiming pending cancellation in an incompatible state are rejected.

Invalid model configuration, unknown edges, missing evidence, wrong roles, identity mismatches, stale revisions and safe-integer overflow reject the transition without mutating the input. Tests and ordered histories must still establish intended behavior; this pure oracle is not evidence of live worker cancellation, broker delivery, storage recovery or production security.
