# TM-223 verification: the test gate leaves the operator dashboard alone

**Change:** `run_tests.sh` runs its own dashboard on a free port and never stops or
restarts the operator's server on 8787 (commit `040aa65`).

## Method

Each run is a full `dashboard/run_tests.sh` gate. A prober runs alongside it as the
operator, with no `AGENTMUX_DASHBOARD` set, so its requests go to 8787:
- it reads the board (`agentmux task show TM-223`) every 20 seconds
- about 4 minutes in, it writes one comment to TM-223 through 8787

A run **passes** only if all of these hold:
- the gate exits 0
- every probe succeeds
- the write lands
- the gate's own exit check reports the 8787 listener's pid and home unchanged

## Run 1

The isolation itself held in run 1: all 59 board probes and the write succeeded, and
8787 was untouched. What failed was `test_residue.sh`.

- **Cause:** that suite's runner cases pinned the OLD contract. They asserted that
  `run_tests.sh` restarts the operator's server onto a test home and restores it
  afterwards. That is exactly the behavior TM-223 removes. Its stub `restart.sh` was
  never called, so its log file did not exist.
- **Fix:** the cases were rewritten to pin the new contract, under the same failure
  modes plus one new one:
  - modes: normal, suite failure, SIGINT, SIGTERM, server fails to start, a caller
    with a different home, and the 8787 listener changing mid-run
  - each case asserts:
    - the operator's server is never restarted
    - exactly one private server starts with `--port` on the test home, and is
      killed on exit
    - the test home is removed
    - the operator's `cc.db` is untouched
    - the suites receive a non-8787 `AGENTMUX_BASE_URL`
    - a swapped listener fails the run
- **Fail check:** all 7 cases fail against the old `run_tests.sh` (each with
  `restarted=True`), and pass against the new one (26 of 26).
